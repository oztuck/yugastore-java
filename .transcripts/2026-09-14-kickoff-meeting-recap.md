Distilled from [2026-09-14-kickoff-meeting.md](2026-09-14-kickoff-meeting.md) (raw transcript).
Team: **"Pirate Brown Pants"** (Team #2), brownfielding Yugastore, demo Friday.

## Business goals (what to build against the app)

1. **CI/microservice deployment for stability** — graceful degradation when a
   service goes down (not a silent failure/hang).
2. **CMS for business rules** (pricing, etc.) — the product catalog is
   **read-only**, seeded once from a JSON file, no create/update/delete.
   Confirmed as an easy architectural fix, not a rewrite.
3. **Fast prototyping / faster design window.**
4. Underlying client ask: "modernize our approach."

## Team's 3-day goals ("our work")

1. **Agent-tool setup, platform-agnostic** — Claude + Copilot mix across the
   team. Plan: `AGENTS.md` as source of truth (Codex/Copilot/Duo-compatible),
   `CLAUDE.md` imports it. Called out as the *first* priority. — **done**,
   see repo root `AGENTS.md` / `CLAUDE.md`.
2. **Agentic team collaboration** — the named pain point: individual AI use
   is easy, but getting devs/testers/PMs collaborating *through* AI with
   shared context is not. Called the *second* priority. — **next up.**
3. **Agent skills + personas** — shared skills (e.g. one story-writing
   convention everyone uses) plus per-role personas (dev/reviewer/tester),
   each with defined techniques/strategy.
4. **Documentation** — human-facing (so e.g. interns can self-serve
   environment setup) and agent-facing, generated by agents.
5. **Shared memory/context** — explicitly "TBD, learning this as we go."
   Rough idea floated: mostly shared markdown files.
6. **Spec-driven development (SDD)** — leaning toward a lightweight approach
   (`requirements.md` / `design.md` / `tasks.md` per feature, Kiro-style)
   rather than a heavier SDD framework.
7. **Story tracking** — no Jira access; leaning toward **GitHub Issues in
   the repo** over Trello/Jira for simplicity and native integration.
8. **Tokenomics** — awareness of token cost/sustainability, avoid burning
   tokens needlessly.
9. **Monitoring/reactive agents** (stretch goal, "lofty but useful") — an
   always-on agent watching logs/metrics that triages and reacts (e.g.
   auto-scaling under load) instead of a human doing it.
10. **Containerization curiosity** — how an agentic workflow interacts with
    containers/deployment; explicitly *not* a hard requirement.
    **No Kubernetes.** Confirmed: local dev runs plain `java -jar`
    processes, only the DB is in Docker.
